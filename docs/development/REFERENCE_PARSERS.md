# 로컬 참고문헌 파서 비교

현재 실험은 MinerU + GROBID + 로컬 Ollama 조합이다. 운영 인용 그래프에
실험 결과를 자동 등록하지 않고 `outputs/reference_benchmark/`에 저장한다.

## 2026-10-17 비교 결과

이 표본에서 권장하는 구성은 **MinerU → 규칙/GROBID 대조 → 불확실한 항목만
Qwen3.6 35B-A3B로 검토**하는 방식이다. 따옴표 제목, 원문 DOI, 합의된 연도를
먼저 보존하므로 LLM이 모든 필드를 새로 작성할 필요가 없다.

| 구성 | 분리한 참고문헌 | 제목 | 개인 저자 성 | 연도 | DOI 표시/부재 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 기존 pypdf + 규칙 | 105/146 | 20/32 | 19/32 | 22/32 | 23/32 |
| MinerU + 블록/번호 검증 + 규칙 | 146/146 | 28/32 | 27/32 | 32/32 | 32/32 |
| MinerU + 블록/번호 검증 + GROBID | 146/146 | 27/32 | 31/32 | 32/32 | 32/32 |
| 규칙/GROBID 결과 조합, LLM 미사용 | 146/146 | 29/32 | 30/32 | 32/32 | 32/32 |
| 위 조합 + Qwen3.6 선택 호출 실제 실행 | 146/146 | 32/32 | 32/32 | 32/32 | 32/32 |

원래 MinerU의 `ref_text` 분류만 사용하면 145개다. 한 항목을 일반 본문으로
분류한 사례는 연속 번호·동일 열·인접 좌표·서지 표기를 확인하는 규칙으로 복구했다.
146/146은 이 7편에서 원문에 있는 번호별 항목을 확인한 결과이며, 모든 항목의
전체 서지 필드나 외부 논문 식별 정확도가 100%라는 뜻은 아니다.

실제 선택 호출은 146개 중 **34개(23.3%)**, 9개 요청 배치를 사용했다.
LLM 호출 시간 합계는 **145.72초**였으며 최초 모델 적재를 포함한다.
기존 파서 결과를 재사용했으므로 이 시간은 PDF 파싱·GROBID 시작을 포함한
전체 실행 시간이 아니다. 원문에 없는 DOI나 제목을 채우기 위한 외부 조회는 하지 않았다.

| 로컬 모델 | 동일 32항목을 LLM에 전달한 시간 | 규칙/GROBID와 결합한 표본 점수 |
| --- | ---: | ---: |
| Qwen3.6 35B-A3B MTP Q4 | 138.48초 | 128/128 필드 |
| gpt-oss 20B | 224.43초 | 128/128 필드 |

32항목 전체 LLM 비교와 146개 중 34항목을 고른 선택 호출은 입력 집합이 다르다.
두 시간을 직접 비교해 선택 호출의 속도 향상 배수를 계산하면 안 된다.
Qwen3.8 27B Q4는 첫 6항목에 **205.52초**가 걸려 속도 기준으로 추가 비교를 중단했다.
이 6항목의 결합 결과는 24/24 필드였고 나머지 26항목은 평가하지 않았다.
모든 Ollama 추론은 이 PC의 CPU에서 실행되었다(`size_vram=0`).

검증에서는 제목이 없는 짧은 인용을 그대로 비워 두는 경우도 정답에 포함했다.
DOI는 표시된 1건과 부재한 31건을 확인한 점수이므로, DOI 32개를 찾아냈다는 뜻이 아니다.
현재 결과는 표본 내 결과이며 별도 논문으로 후속 검증해야 한다.

관련 단위·회귀 테스트 **40개**와 실제 파서/로컬 LLM 실행을 확인했다.

## 확보한 구성

| 구성 | 고정 버전 | 역할 |
| --- | --- | --- |
| MinerU | 4.0.10 | PDF 레이아웃과 `ref_text` 블록 추출. 기존 Basic ONNX CPU 환경 재사용 |
| GROBID | 0.9.1 CRF | MinerU 또는 pypdf에서 분리한 참고문헌 문자열의 서지 필드 추출 |
| Ollama | 0.40.4 | 불확실한 서지 필드의 로컬 구조화 추출. 기존 설치 모델 사용 |
| Eclipse Temurin | JDK 21.0.12.1+1 | 저장소 내부 GROBID 실행용 Java |

원본 소스는 `.runtime/reference-tools/sources/{mineru,grobid,ollama}/`에 있다.
각 프로젝트의 공식 태그와 커밋을 고정한 sparse checkout이며 원본 라이선스를 포함한다.
고정 정보는 `config/reference_tools.lock.json`, 실제 설치 상태와 모델 해시는
`.runtime/reference-tools/acquired.json`에 기록한다.
Ollama 모델 파일은 기존 로컬 모델 저장소를 사용하며 중복 복사하지 않는다.

GROBID 공식 CRF OCI 배포물을 체크섬 검증 후 일반 파일로 추출했다.
Docker 데몬, 컨테이너, WSL 또는 시스템 Java를 설치하지 않는다.
공식 Windows Wapiti DLL과 격리 Java로 **참고문헌 문자열 파싱**을 실행한다.
Linux용 pdfalto를 사용하는 GROBID의 PDF 전체 파싱과 동일한 실행 방식은 아니다.
GROBID의 외부 서지정보 보완(consolidation)은 `0`으로 꺼 둔다.

## 재현

프로젝트 루트의 PowerShell에서 실행한다.

```powershell
# 공식 배포물과 소스를 명시적으로 다운로드. 파일은 .runtime 아래에 둔다.
.venv/Scripts/python.exe scripts/setup_reference_benchmark.py --fetch

# 파일·소스 커밋 확인. --online은 로컬 Ollama 상태만 읽고 추론하지 않는다.
.venv/Scripts/python.exe scripts/reference_parser_status.py --online

# 현재 설치된 MinerU 런타임 확인
.runtime/document-parsers/Scripts/python.exe scripts/document_parser_status.py

# 논문 7편의 참고문헌 페이지에 파서 적용
.venv/Scripts/python.exe scripts/benchmark_reference_parsers.py --prepare

# 동일한 원문 필드를 로컬 모델별로 비교
.venv/Scripts/python.exe scripts/benchmark_reference_parsers.py --models qwen3.6:35b-a3b-mtp-q4_K_M gpt-oss:20b qwen3.8:27b-q4_K_M

# 모든 참고문헌 중 불확실한 항목만 선택해 LLM 호출
.venv/Scripts/python.exe scripts/benchmark_reference_parsers.py --adaptive-model qwen3.6:35b-a3b-mtp-q4_K_M
```

MinerU 설치·모델 준비는 기존 [DOCUMENT_PARSERS.md](DOCUMENT_PARSERS.md)를 따른다.
이 스크립트는 웹 서버 가상환경에 모델 패키지를 추가하지 않는다.
운영 AI 작업이 없는 시간에 모델 비교를 실행하는 것이 좋다.

## 비교 기준과 한계

- PDF 7편, 원문에서 확인한 참고문헌 146개, 서지 필드 검증 표본 32개다.
- 표본에는 두 단 편집, 두 페이지에 걸친 참고문헌, 표/약력 혼입,
  숫자로 시작하는 제목, 제목을 쓰지 않은 짧은 참고문헌, 보고서·표준·책을 포함했다.
- 제목·첫 개인 저자의 성·발행연도·DOI 4필드를 평가한다. 기관 저자는 원문에
  남기고 개인 성 필드에 넣지 않는다. 이 필드가 전체 저자 목록을 뜻하지는 않는다.
- 비교는 유니코드 정규화 후 구두점·공백·대소문자를 무시한 일치 여부다.
  원문 참고문헌 자체의 사실 오류나 외부 DOI 연결 정확도를 검사한 것은 아니다.
- 검증 표본의 DOI는 원문에 표시된 1개와 표시되지 않은 31개다.
  이 표본으로 일반적인 DOI 추출 재현율을 추정할 수 없다.
- `11509475`의 참고문헌 8번은 원문 표기를 따라 `UCle Standard Specification`으로
  평가한다. 일반적으로 알려진 표준명으로 자동 교정하지 않는다.
- LLM 단독 비교는 32개 검증 항목의 필드만 LLM으로 처리한다. 나머지 항목의
  필드 정확도까지 검증한 결과가 아니다. 참고문헌 항목 분리는 MinerU가 담당한다.
- 선택 호출(adaptive)은 146개 전체 중 규칙이 불확실하다고 판정한 항목을 처리한다.
- 모델별 시간은 호출 응답 시간이며 최초 모델 적재 시간도 포함한다.
  MinerU 결과 캐시를 재사용한 경우를 추론 0초로 해석하면 안 된다.
- 같은 표본으로 오류를 분석하고 검증 규칙을 보완했다. 표본 내 결과이며,
  새로운 논문에 대한 일반화 성능이나 모든 조합의 전역 최적값을 보장하지 않는다.

## 선택 호출 규칙

1. MinerU가 참고문헌으로 분류한 블록을 사용하고 페이지·좌표·원문을 보존한다.
2. 연속 번호를 검증한다. 바로 아래 같은 열의 일반 텍스트 블록은 번호·간격·
   연도·서지 표기가 맞을 때만 마지막 참고문헌 후보로 복구한다.
3. 따옴표로 경계가 명확한 제목과 원문에 표시된 DOI는 결정적으로 추출한다.
4. GROBID의 필드와 대조하고, 제목이 없거나 따옴표가 없거나 저자·연도가
   불일치하면 LLM 검토 대상으로 삼는다.
5. LLM 결과도 원문 문자열에 근거가 있어야 한다. 없는 제목·DOI는 만들지 않는다.
   확실한 따옴표 제목·DOI·합의된 연도는 LLM 결과로 덮어쓰지 않는다.
6. 이 검증은 서지 필드 후보를 만드는 절차다. 실제 논문 간 인용 연결은 별도로
   DOI/SQL 식별과 출처 근거를 확인해야 한다.

재현 코드, 버전 고정 정보, 평가용 서지 필드 표본은 저장소 코드에 포함한다.

## PDF 500개 1차 배치

2026-10-17에 별도 표본으로 500개 시험을 시작했다. 기존 7편은 제외하며,
파일 SHA256으로 중복을 제거한 뒤 출판사별 비율과 고정 해시 순위로 선정한다.
선정 결과는 IEEE 441개, Optica 55개, Nature 4개다. 잡지 소개글 등도
보유 PDF 표본에 들어갈 수 있으므로 500개 모두가 정규 연구논문인 것은 아니다.

```powershell
.venv/Scripts/python.exe scripts/benchmark_reference_bulk.py --select
# 아래 두 단계는 별도 프로세스로 실행할 수 있다.
.venv/Scripts/python.exe scripts/benchmark_reference_bulk.py --prepare
.venv/Scripts/python.exe scripts/benchmark_reference_bulk.py --enrich --follow
# 실행 중 진행률 갱신, 종료 후 원문 해시·번호·필드 근거 검사
.venv/Scripts/python.exe scripts/report_reference_bulk.py
```

기본 결과 폴더는 `outputs/reference_bulk_500_20261017/`이다.
`manifest.json`은 고정 표본, `progress.json`과 `RUN_STATUS.txt`는 진행률,
`summary.json`은 처리량, `quality-review.json`은 구조 검사와 역할 검토 후보,
`final-verification.json`은 전체 종료 후 검증 결과다. 종료 전에는 마지막 파일이 없다.
프로세스가 중단되면 같은 명령으로 저장된 단계부터 재개할 수 있다.
다른 표본을 만들려면 `--out`으로 새 폴더를 지정한다.

MinerU는 로컬 ONNX 기본 모델을 재사용하는 전용 프로세스로 실행하며, GROBID는
최대 25개 PDF의 참고문헌을 한 JVM에서 처리한다. LLM은 Qwen3.6 35B-A3B MTP Q4를
순차 호출한다. 컨텍스트 8192, 출력 최대 2048, temperature 0.1, thinking 꺼짐,
최대 5개 항목·원문 6000자 묶음이다. 토큰 상한·번호·JSON 검증에 실패하면
묶음을 나누고, 단일 항목도 실패하면 그 항목을 검토 대상으로 남긴다.
운영 AI 대기/실행 작업이 있으면 LLM 호출 전에 양보한다. 작업 상태 확인은
읽기 전용이며, 추출 결과를 운영 SQL이나 인용 그래프에 쓰지 않는다.

초기 PDF 대조에서 두 파서가 합의한 성을 LLM이 이름으로 덮어쓰는 오류를 확인해
합의된 성을 보존하도록 수정했다. 제목 없이 학회와 쪽수만 적은 것이 명확한
짧은 인용은 제목을 빈값으로 유지하고 불필요한 호출을 생략한다. 제목과 학술지명이
동일한 LLM 결과는 제목 후보에서 제외한다. 수정 전 8개 PDF 결과는
`before-role-fix/`에 보존했다. 이 표본에 맞춘 수정은 일반 정확도 보증이 아니다.

이번 배치는 연속된 `[1]` 번호 형식을 검증한다. `1.` 번호나 번호 없는 목록은
`no_references` 등으로 따로 남기며, 실제 참고문헌이 없다는 뜻으로 해석하지 않는다.
500개 전체에 수작업 정답이 없으므로 처리 성공률·필드의 원문 포함 여부를
서지정보 정확도로 표현하면 안 된다. DOI가 원문에 없으면 외부 조회로 보충하지 않는다.

실제 묶음에서 NULL 제어문자 6개가 GROBID 토큰 정렬 오류를 일으켜 226개 항목
전체의 처리를 중단한 사례도 확인했다. 원본 문자열은 보존하고 CRF 입력에서만
XML에 부적합한 C0 문자를 제거하며, 묶음 오류가 나면 항목별로 재시도한다.
같은 226개 항목의 재처리는 모두 반환됐다. 수정 전 결과는
`before-grobid-isolation-fix/`에 보존했다. GROBID 어댑터만 바뀐 경우에는 모델
해시·프롬프트·추론 설정·입력이 모두 같은 LLM 캐시만 재사용하고 이력을 남긴다.

추가로 고정 표본 순서 50/100/150/200/250/300/350/450번째 PDF의 원본 페이지를
모델 필드를 보기 전에 대조했다. 이 8편은 모두 IEEE 논문이다. 참고문헌 32개,
127개 필드와 문헌 개수를 `holdout-audit-gold.json`에 기록하며, `holdout-score.json`과
최종 검증 파일에서 GROBID·LLM 전후 점수를 비교한다. DOI가 표시된 항목은 4개다.
성의 경계가 불명확한 `N. D. Dalt` 1건은 저자 필드 채점에서 제외했다.

## 제목 표시 정규화와 500개 캐시 재검증

최종 필드 선택 뒤 `reference_normalization.py`를 적용한다. 원래 `raw`, `title`,
저자·연도·DOI는 보존하며 `title_display`, `title_match_key`, `reference_type`,
버전·변환 단계·경고를 추가한다. 검색키는 연산자와 아래첨자 구분을 보존한다.
표시 제목과 검색키는 후속 연결을 위한 후보이며 운영 SQL에 자동 등록하지 않는다.

- 제목 끝 `[J]`·`[C]`는 원문에서 학술지/학회명과 연도가 뒤따르는 경우만
  문헌 종류로 분리한다. 제목 내부의 대괄호나 따옴표 안에 포함된 표식은 지우지 않는다.
- 수식은 길이·중첩 한도를 둔 파서로 변환한다. 예를 들어
  `$1 . 3 \mathrm{V}_{\mathrm{p p d}}$`는 `1.3 V_ppd`로 표시한다.
  숫자·단위·부호를 임의로 삭제하지 않으며 알 수 없는 명령은 검토 대상으로 남긴다.
- 깨진 소수점·수식 구분자는 같은 PDF의 같은 페이지·참고문헌 번호를 PDFium으로
  다시 읽는다. 파일 해시, 저자·연도, 충분한 공통 제목 문자열과 따옴표 경계를
  확인한 경우만 복구한다. 원문·해시·파서 버전을 증거로 저장한다. 근거가 부족하거나
  복수 후보가 남으면 표시 제목과 검색키를 비워 검토 대상으로 둔다.
- PDF 복구는 독립 프로세스의 텍스트 추출이며 LLM이나 외부 API를 호출하지 않는다.
  PDF 이미지 OCR만으로 재판독해야 하는 사례는 이 단계에서 자동 해결하지 않는다.
- 정규화 코드가 바뀌어도 입력·모델·프롬프트·추론 설정이 같은 LLM/GROBID 캐시는
  재사용한다. 최종 결과와 PDF 증거는 별도 버전 및 코드 해시로 구분한다.

기존 배치를 덮어쓰지 않고 후처리만 재실행하려면 다음을 사용한다.

```powershell
.venv/Scripts/python.exe scripts/revalidate_reference_titles.py
# 재실행할 때는 기존 결과와 겹치지 않는 새 --out 폴더를 지정한다.
```

## 출판사 근거로 남은 저자명 1건 수정

`7168640.pdf`의 참고문헌 2번은 `Chen Shuai`를 성이 먼저 오는 순서로 적었다.

## 원인에 따른 v5 파이프라인 개선

100편 검증에서 확인한 159개 필드 오류 중 124개는 항목 자체의 누락이 원인이었다.
나머지 35개는 역할 해석·문자 손실 문제였다. 필드 추출기를 더 호출하는 것보다
참고문헌 경계와 역할 근거를 먼저 검증하도록 배치 절차를 바꿨다.

- `reference_segmentation.py`: 명시적 참고문헌 영역 안에서 `[1]`, `1.` 및 한 줄
  다중 인용을 구분한다. 연속 번호와 서지 단서를 확인하고 그림·표·저자 소개·
  머리말·바닥글을 제외한다. 독립 추출 결과가 경계 결함을 확인한 경우만 원래
  경계를 교체한다. 해석하지 못한 목록은 `extraction_unresolved`로 남긴다.
- `reference_roles.py`: 파서의 합의도 원문의 서지 역할과 다시 대조한다.
  개인의 성과 기관명(`author_organization`), 반복 저자, 명확한 복합 성을 구분한다.
  제목·보고서 대상 기간·접속일·페이지 번호·문헌 식별자·DOI의 숫자는 발행연도와
  구분한다. 역할을 확정할 수 없는 경우 후보를 보존하고 검토 상태를 유지한다.
- `reference_evidence.py`와 `reference_evidence_worker.py`: PDFium을 격리 런타임에서
  실행하고 PDF·실행 코드 해시로 증거 캐시를 구분한다. 지수는 실제 글자의 크기와
  높이 차이가 확인될 때만 복원한다. 번호만으로 서로 다른 문헌을 연결하지 않는다.
  기존 수식·아래첨자나 단위를 더 단순한 PDF 텍스트가 덮어쓰지 못하게 한다.
- `reference_pipeline.py`: 신규 배치와 캐시 재검증에 같은 최종 단계를 적용한다.
  원문 `raw`를 보존하고 필드 변경 전후 값, 규칙, 별도 텍스트 증거와 해시를 남긴다.
  새로 발생한 검토 사유는 이전 정규화 상태가 지우지 못하게 한다.
- 배치의 LLM 캐시는 실제 프롬프트 입력인 번호·원문과 모델·프롬프트·생성 설정으로
  구분한다. 후처리 변경만으로 같은 입력을 다시 추론하지 않는다. 일부 성공한
  응답도 번호로 다시 연결해 다른 항목으로 응답이 밀리지 않게 한다.
- 완료된 실험 폴더에 `--prepare`·`--enrich`를 실행하면 거부한다. 새 `--out`
  경로를 지정해야 하며, 완료 결과와 개발 중간 결과는 별도로 보존한다.

같은 100편의 고정 정답으로 재검사한 최종 결과는
`outputs/reference_pipeline_v5_regression_20261017/`에 저장했다.

개선됐다. 400개 표본 참고문헌의 필드 오류는 159/1,599개(9.94%)에서
4/1,599개(0.25%)로 감소했고, 기존 정답에서 새로 발생한 오류는 없었다.
제목 2/400, 첫 저자 성 2/399개가 남았고 연도·DOI는 각각 0/400개 오류였다.
남은 4개는 잘못된 저자 글자, 글꼴 인코딩으로 소실된 지수·단위, 불명확한

## 텍스트 우선 추출과 OCR 보완

2026-10-17 사용자 요청에 따라 `prepare` 단계는 먼저 pypdf/PDFium으로
글자 데이터를 추출하고 참고문헌 경계를 확인한다. 네이티브 참고문헌 제목이
확인된 경우 그 페이지 이전의 본문·그림은 OCR 대상에서 제외한다. 글자가
없거나 매우 적거나 깨진 페이지에만 로컬 Tesseract.js 7.0.0 영어 OCR을
적용한다. 짧아도 정상적으로 분리된 네이티브 참고문헌은 OCR하지 않는다.
텍스트 또는 OCR로 분리에 성공하면 무거운 MinerU 처리는 건너뛴다.
두 방법으로도 해결되지 않은 레이아웃만 기존 MinerU 경로를 사용한다.

OCR은 이미 설치된 Node.js·Tesseract.js와
`outputs/serdes_ocr/eng.traineddata`를 사용한다. 외부 API·원격 LLM 호출이나
모델 다운로드는 하지 않는다. `SERDES_OCR_NODE`로 Node 경로를 지정할 수
있다. 엔진이나 모델이 없거나 시간 초과가 발생하면 사유를 기록하고
`extraction_unresolved` 또는 검토 대상으로 남긴다. 참고문헌 0개로 확정하지 않는다.

네이티브 텍스트, OCR 원문, 실제 페이지 번호, 페이지 이미지와 단어 좌표·신뢰도는
함께 보존한다. PDF·모델·코드·설정 해시가 같은 작업은
`.runtime/reference-ocr-cache/`를 재사용한다. OCR은 최대 24페이지까지 처리하며
예산을 초과하면 경고와 미처리 후보 목록을 기록한다. 일부 페이지만 읽고 전체
PDF에 참고문헌이 없다고 판단하지 않는다.

두 단 문서에서 별도 열로 인식된 번호는 같은 줄의 가까운 본문에만 연결한다.
실제 열 사이의 빈 간격으로 읽기 순서를 복구한다. `2%`처럼 오인식된 번호는
원래 이미지의 해당 줄을 다시 읽고, 숫자 패턴과 신뢰도가 충족될 때만 복구한다.
예상 번호를 이용해 빈 번호를 만들지는 않는다. 이 복구 이력도 근거에 남긴다.

이미지 PDF `optica-10-7-832.pdf`에서 1–27번을 모두 분리했다. 영어 OCR
9페이지 처리에는 약 29초가 걸렸고, 이후 실제 배치 준비에서는 캐시를 재사용했다.
`OFC-2023-Th2A.2.pdf`는 OCR 없이 텍스트로 9개 번호 항목을 분리했다.
두 파일 모두 MinerU가 실행되지 않았음을 실제 준비 단계에서 확인했다.

URL 수정 후의 동일한 100편과 비교하면 기존 1,292개 항목의 서지 필드 변경이나
항목 삭제 없이 27개를 추가했다. 참고문헌 개수 일치는 98→99/100편이며,
고정 표본 1,534개 필드의 불일치는 55→42개다. 새 독립 정확도 평가는 아니다.
OCR 파일의 표본 16개 필드 중 3개는 여전히 불일치한다. 연도 판정 1개,
부등호 1개, 제목 단어 1개이며 자동 확정하지 않는다. OCR 근거를 사용한
27개 항목 모두 `ocr_source_requires_review`로 표시한다. 추가 검토로 고정 정답을
수정하거나 단건 보정 규칙을 넣지 않았다.

자동 검사 129개와 100편 PDF 해시·구조 감사가 통과했다.
결과는 `outputs/reference_ocr_fallback_20261017/final100-regression/`,
요약은 같은 상위 폴더의 `verification.json`, `VERIFICATION.txt`에 보존했다.
기존 500편·평가 정답·운영 SQL에는 쓰지 않았으며 새 로컬 LLM 호출도 없다.

## 실제 준비 단계부터 다시 돌린 200편 백테스트
